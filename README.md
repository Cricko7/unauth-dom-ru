Веб-приложение команды **Solid Eagle**, созданное по кейсу «Дом.ру»: проверить соединение, пройти диагностику, посмотреть Wi-Fi рядом и задать вопрос ИИ-ассистенту из одного интерфейса.

## Возможности

- Регистрация и вход по номеру телефона и паролю, авторизация через cookie.
- Измерение download/upload и оценка задержки между браузером и сервером приложения.
- Диагностика подключения с отдельной страницей результата.
- Wi-Fi-раздел с картой Яндекса и демонстрационными карточками точек.
- ИИ-помощник по вопросам интернета, роутеров и Wi-Fi через внешний API.
- Светлая и тёмная темы, адаптивная вёрстка.

Это прототип: SMS-подтверждение, реальное подключение к Wi-Fi-точкам и интеграция с личным кабинетом оператора не реализованы. Для ответов ИИ нужны действующий ключ и квота провайдера. Демо пока работает по HTTP; HTTPS-конфигурация подготовлена для домена.

## Ценность до подключения

В кейсе ЭР-Телеком поставлена задача развить неавторизованную зону «Мой Дом.ру»: дать человеку полезный повод открыть приложение ещё до заключения договора и сформировать путь к подключению. Наш подход — начать с повседневной задачи пользователя: «почему интернет работает хуже и что с этим сделать?».

Веб-прототип позволяет открыть диагностику без входа, задать параметры подключения, получить реальные измерения и перейти к понятным рекомендациям. Пользователь знакомится с сервисом через собственную задачу; Wi-Fi-раздел и ИИ-ассистент дополняют этот сценарий. Полный путь до заявки и договора — следующий этап интеграции с оператором.

## Сильные стороны реализованного решения

| Сильная сторона | Что уже работает | Польза |
| --- | --- | --- |
| Доступность до договора | Главная, диагностика, результат и спидтест открываются без авторизации и установки приложения | Пользователь может сразу попробовать сервис в браузере |
| Реальные измерения соединения | Download/upload проходят через собственный API, клиент вычисляет скорость и оценивает задержку HTTP-запросов | Результат опирается на передачу данных, а не на заранее заданные значения скорости |
| Связный сценарий диагностики | Форма провайдера, тарифной скорости, роутера и типа подключения → измерение → страница результата | Контекст проверки собирается в одном пользовательском пути |
| Понятный результат | Сравнение download с выбранной тарифной скоростью, итоговый индикатор, рекомендации, повторный тест и печать результата | Измерения можно интерпретировать и сохранить через диалог печати браузера |
| Вход без номера договора | Регистрация и вход по телефону и паролю через ASP.NET Identity | Учётную запись можно создать до подключения услуг оператора |
| Единый интерфейс | Общая навигация, светлая/тёмная тема с сохранением выбора, Wi-Fi-карта и интерфейс чата | Сервисы доступны из одной оболочки |
| Работающий публичный прототип | Развёртывание на VPS, контейнеры приложения/БД/прокси, автоматический CI/CD и бэкап перед деплоем | Решение можно показать и воспроизвести; проверены вход и сохранность данных/сессии при пересоздании контейнеров |

Измерения характеризуют соединение браузера с сервером приложения. Индикатор качества — эвристика прототипа; отдельного измерения потерь пакетов и аппаратной диагностики роутера пока нет. Форма собирает модель роутера и способ подключения, но текущий расчёт оценки их не использует. Рекомендации на странице результата пока общие. Подробнее о соответствии презентации коду — в [описании продукта](docs/PRODUCT.md).

## Предложения команды по развитию

В презентации Solid Eagle выделены три направления следующего этапа:

- **AR-тепловая карта сигнала:** поиск «мёртвых зон» Wi-Fi в квартире через камеру смартфона.
- **Демо-витрина Movix и Умного дома:** интерактивный просмотр демонстрационных камер двора и подборок ТВ-каналов до оформления услуг.
- **Мониторинг безопасности сети:** уведомления о незнакомых устройствах в домашнем Wi-Fi.

Эти функции предложены для развития и пока не реализованы. Их пользовательская ценность, технические зависимости и границы текущего MVP описаны в [плане развития](docs/ROADMAP.md).

## Быстрый локальный запуск

Нужны Git, Docker Engine/Desktop с Linux-контейнерами и Docker Compose v2 или новее. .NET SDK на хосте для этого варианта не требуется.

```bash
git clone https://github.com/Cricko7/unauth-dom-ru.git
cd unauth-dom-ru
cp .env.example .env
```

В PowerShell вместо последней команды: `Copy-Item .env.example .env`. Заполните `POSTGRES_PASSWORD` в `.env` случайной hex-строкой длиной от 32 символов. `AI_API_KEY` можно оставить пустым, если чат не нужен. `.env` не попадает в Git и Docker build context.

```bash
docker compose up -d --build --wait --wait-timeout 240
```

Откройте **http://localhost:8080**. PostgreSQL и таблицы создаются миграциями автоматически. Публичная схема без данных и порядок работы с предоставленным архивом описаны в [database/README.md](database/README.md).

```bash
curl --fail http://localhost:8080/health
python3 deploy/smoke.py
docker compose logs --tail=100 web db
docker compose down
```

В Windows используйте `curl.exe` и `python`, если так называются установленные команды. Smoke-тест создаёт тестовый аккаунт. Обычный `down` сохраняет данные; `down -v` удаляет тома и нужен только для одноразовых тестовых окружений.

## Структура репозитория

```text
.
├── DoomRu.sln                  # решение Visual Studio / dotnet
├── DoomRu/                     # основное ASP.NET Core приложение
│   ├── Controllers/            # JSON API: чат и спидтест
│   ├── Data/                   # EF Core / Identity-контекст
│   ├── Models/                 # DTO чата и вспомогательные модели
│   ├── Migrations/             # InitialCreate и snapshot схемы
│   ├── Pages/                  # страницы Razor, Auth и общий layout
│   ├── Services/               # клиент внешнего ИИ API
│   ├── wwwroot/                # CSS, JS, изображения и vendor-библиотеки
│   ├── Properties/             # локальные профили запуска
│   └── Program.cs              # DI, middleware, маршруты и создание БД
├── 123/                        # отдельный исходный HTML-прототип
├── database/                   # публичная схема и переход на миграции
├── docs/                       # продукт, развитие, API, архитектура и CI/CD
├── deploy/                     # deploy-скрипты, Caddy и smoke-тест
├── .github/workflows/          # GitHub Actions
├── Dockerfile                  # многоэтапная сборка приложения
├── compose*.yaml               # БД, приложение, HTTP/HTTPS и dev override
└── .env.example                # шаблон приватных настроек
```

Рабочий интерфейс находится в `DoomRu/Pages` и `DoomRu/wwwroot`. Папка `123` сохраняет HTML-прототип и не публикуется приложением. Потоки запросов и модель хранения описаны в [архитектуре](docs/ARCHITECTURE.md).

## API в одном экране

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/health` | Проверка подключения к БД |
| POST | `/api/aichat/send` | Сообщение ассистенту и история диалога |
| GET | `/api/speedtest/download?mb=10` | Случайные байты для измерения download |
| POST | `/api/speedtest/upload` | Приём тела запроса для измерения upload |

Форматы, ограничения, примеры curl и особенности ошибок — в [API.md](docs/API.md). Вход и регистрация работают через Razor-формы, а не JWT API.

## Разработка и вклад

Создайте ветку, внесите изменения и откройте pull request. CI собирает контейнеры и проверяет API, статику, авторизацию и сохранение данных/сессии при пересоздании контейнеров. После успешного CI изменения в `main` автоматически развёртываются, если включён CD и настроены секреты. См. [CI/CD](docs/CI-CD.md).

Секреты, локальные БД, бэкапы, `bin`, `obj` и кэш IDE не коммитятся. Схема БД версионируется через EF Core migrations и обновляется при старте. Переход со старого `EnsureCreatedAsync` описан в [инструкции по БД](database/README.md). Проект распространяется по [MIT License](LICENSE).
