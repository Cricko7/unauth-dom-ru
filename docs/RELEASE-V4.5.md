# Обновление V4.5

[← README](../README.md) · [База данных](../database/README.md) · [API](API.md)

Обновление основано на предоставленных исходниках DoomRu V4.5, архиве Doomru.sql и описании разработчика PeakMe.docx. Исходные документы описывают намерения и устройство версии; фактическая конфигурация проверяется по коду репозитория.

## Исправления

- Регистрация нормализует маску телефона, пробелы, скобки и дефисы в `+7XXXXXXXXXX`; принимаются варианты с `8` и с десятью цифрами без кода страны.
- Форма входа разделяет видимое поле с маской и скрытое значение, отправляемое серверу. Сервер дополнительно нормализует номер.
- Номер может подставляться в форму входа из query string. После входа поддерживается локальный `returnUrl` через `LocalRedirect`.
- Контекст Identity приведён к компактной форме; добавлены InitialCreate, designer и model snapshot.
- Старт приложения переведён с `EnsureCreatedAsync` на `MigrateAsync`; гостевые страницы явно перечислены в настройках Razor Pages.

При объединении сохранены ранее проверенные `/health`, Docker/Compose, постоянные ключи сессий, forwarded headers для Caddy, CI/CD и включение изображений в publish. Исходники авторизации приведены из Windows-1251 к UTF-8 для сборки в Linux. Пароли и API-ключи из локального appsettings не публикуются.

## База данных

В предоставленном custom archive находятся стандартные таблицы Identity, история миграций и одна учётная запись. Публичный `database/schema.sql` содержит только структуру; исходный архив хранится приватно. Для старой production-схемы предусмотрен проверяемый [переход через baseline](../database/README.md), который не удаляет существующие аккаунты.

## Уточнения к документации разработчика

| Утверждение исходного описания | Актуальное состояние репозитория |
| --- | --- |
| ASP.NET Core / SDK 8 | `TargetFramework=net9.0`; Docker и CI используют .NET 9 |
| Отдельного health endpoint нет | `/health` проверяет PostgreSQL и используется Docker/CD |
| Ключ хранится в appsettings.json | Публичный appsettings не содержит секрета; VPS получает ключ из закрытого `.env` |
| Пример модели DeepSeek-V4-Flash | В поставленных исходниках остаётся DeepSeek-R1-0528; доступность моделей зависит от провайдера |
| Интеграционные тесты ещё не реализованы | CI проверяет реальные контейнеры PostgreSQL/приложения, авторизацию и сохранность данных |
| Дата создания пользователя хранится в БД | В текущем стандартном `IdentityUser` и схеме такого поля нет; для него нужна отдельная модель/миграция |
| Wi-Fi-квест и личный кабинет | Квест остаётся статическим; прогресс в БД, тарифы и роутеры личного кабинета — будущие задачи |

Актуальные участники и контакты Solid Eagle перечислены в README.

## Проверки обновления

Smoke-тест проверяет регистрацию с форматированным номером `8 (...) ...-..-..`, вход по десяти цифрам, локальный returnUrl, повторный вход и сохранность сессии после пересоздания контейнеров. В CI также проверяется переход существующей схемы через baseline. Платный внешний ИИ API для этих тестов не вызывается.
