# Предложения Solid Eagle по развитию

[← README](../README.md) · [Реализованный MVP](PRODUCT.md)

Источник продуктовых предложений — слайд 10 «Планы на будущее: Развитие продукта» презентации команды Solid Eagle. Все три направления ниже пока находятся на стадии предложения. Технические зависимости — пояснения к будущей реализации, а не уже выполненные работы или утверждённые сроки.

## 1. AR-тепловая карта сигнала

**Идея команды:** поиск «мёртвых зон» Wi-Fi в квартире через камеру смартфона.

Пользователь проходит по квартире и видит, где покрытие хуже. Такой сценарий может помочь выбрать место для роутера и понять, нужна ли дополнительная точка доступа.

Для реализации потребуются измерения характеристик Wi-Fi, привязка замеров к положению устройства и AR-визуализация. Одна камера не измеряет радиосигнал; нужно проверить доступность сетевых данных и пространственных API на целевых мобильных платформах. Текущий браузерный спидтест не строит карту покрытия.

## 2. Демо-витрина Movix и Умного дома

**Идея команды:** интерактивный просмотр камер двора и подборок ТВ-каналов.

Предлагаем дать человеку возможность попробовать демонстрационные сценарии цифрового дома до подключения: увидеть пример просмотра камеры и познакомиться с подборками контента Movix. Это продолжает задачу кейса — показать пользу экосистемы до договора.

Для реализации нужны согласованные демонстрационные видеопотоки/контент, интеграции с сервисами и понятный переход к подключению выбранной услуги. Демонстрация камер должна использовать специально подготовленные материалы; доступ к камерам реальных пользователей из гостевой зоны не предполагается. В текущем приложении интеграций с Movix и Умным домом нет.

## 3. Мониторинг безопасности сети

**Идея команды:** уведомления о незнакомых устройствах в домашнем Wi-Fi.

Пользователь видит новое устройство и может проверить, принадлежит ли оно домашним. Такой сервис создаёт повод возвращаться в приложение после первой диагностики.

Для реализации потребуется источник списка устройств — например, интеграция с поддерживаемым роутером, — сохранение доверенных устройств и механизм уведомлений. Нужно определить поддерживаемое оборудование и необходимые разрешения. Обычная веб-страница не получает список всех устройств домашней сети автоматически; текущий прототип такого доступа не имеет.

## Основа для дальнейшего развития

В MVP уже есть гостевой вход в сценарий диагностики, собственный API измерений, результат, учётные записи и инфраструктура размещения. Перед расширением продукта нужно завершить функции, показанные в концепции: реальный Wi-Fi-квест и промокоды, каталог точек, рекомендации по оборудованию и путь до заявки на подключение.

Эти доработки следуют из сравнения концепции с кодом и перечислены в [PRODUCT.md](PRODUCT.md). Они не являются дополнительными направлениями со слайда 10. Приоритеты, бюджет и сроки трёх новых направлений командой в предоставленной презентации не зафиксированы; горизонт 3–6 месяцев относится к рамкам кейса, а не к гарантии готовности всех предложений.
